 Monocular Visual Odometry — Fault Analysis & Research Paper Improvement Guide

  Executive Summary

  This is a well-structured, modular implementation of a monocular VO pipeline with impressive documentation and mathematical rigor.
  However, there are several critical correctness bugs that would invalidate published results, plus architectural gaps that need
  addressing for a competitive research paper.

  ---

  🔴 CRITICAL CORRECTNESS BUGS (Must Fix Before Any Publication)

  1. PnP Path Breaks the Pose Graph (odometry.py:192-239)

  Location: VisualOdometry.process_frame() lines 192-239
  - When PnP succeeds (lines 197-207), it sets self._current_R/self._current_t but leaves pose = None
  - Later _process_keyframe() is called with pose=None (line 239)
  - This causes no odometry edge to be added (line 424: if pose is not None)
  - No landmarks added (line 435: if pose is not None)
  - Result: Once PnP takes over, the pose graph becomes disconnected — loop closure can never work, optimization has no edges

  Fix: Create a PoseEstimate from PnP result:
  if pnp_result is not None:
      R_pnp, t_pnp, inlier_mask_pnp = pnp_result
      n_pnp_inliers = int(inlier_mask_pnp.sum())
      if n_pnp_inliers >= 6:
          pose = PoseEstimate(
              R=R_pnp, t=t_pnp / self._scale_recovery.scale,  # unit translation
              E=np.eye(3),  # dummy for PnP
              inlier_mask=inlier_mask_pnp,
              n_inliers=n_pnp_inliers,
              n_total=n_pnp_inliers,
          )
          used_pnp = True

  2. Trajectory Never Updated After Optimization (odometry.py:470-482)

  Location: VisualOdometry._process_keyframe()
  - After loop closure triggers optimization (line 476), it syncs only the current frame's node (lines 478-481)
  - The _trajectory list (per-frame poses) is never updated with optimized values
  - Saved trajectory and ATE/RPE metrics use pre-optimization poses
  - Published results would not reflect the "optimized" system

  Fix: After optimization, rebuild trajectory from optimized graph:
  # After line 476
  optimized_poses = []
  for fid in self._pose_graph._node_order:
      node = self._pose_graph.get_node(fid)
      optimized_poses.append(node.T)
  # Need to interpolate for non-keyframes or re-run forward pass

  3. Pose Graph Edge Residual Convention Bug (pose_graph.py:340-343)

  Location: PoseGraph.compute_edge_error()
  # Current (WRONG):
  T_ij_pred = se3_compose(se3_inverse(T_i), T_j)  # T_i^{-1} @ T_j = j→i
  # Should be:
  T_ij_pred = se3_compose(se3_inverse(T_j), T_i)  # T_j^{-1} @ T_i = i→j
  - Measurement convention: T̂_ij = transform from i → j (lines 197, 285-286)
  - Prediction computes j → i (inverse)
  - Optimizer minimizes wrong residual — converges to incorrect solution
  - Test at line 132-143 passes by coincidence (degenerate case)

  4. LocalMap Coordinate Frame Inconsistency (local_map.py:160-183)

  Location: LocalMap.add_keyframe()
  - cv2.triangulatePoints(P_prev, P_curr, ...) returns points in previous keyframe's camera frame
  - But chirality check (171-173): X_cam2 = R @ X + t treats X as world coordinates
  - Reprojection (176): self.camera.project(X, R, t) also treats X as world coordinates
  - Parallax check (181): X - t_prev mixes camera-frame X with world-frame t
  - All geometric checks are invalid — landmarks stored with wrong positions

  Fix: Convert to world coordinates before storing:
  # After triangulation:
  X_world = se3_inverse(T_prev)[:3,:3] @ X + se3_inverse(T_prev)[:3,3]
  # Then all checks use X_world with T_curr, T_prev

  5. Keyframe Triangulation Uses Unmatched Points (odometry.py:439-448)

  # Current (WRONG):
  prev_kps = self._prev_kps if self._prev_kps is not None else np.empty((0, 2))
  max_pts = min(500, len(prev_kps), len(kps))
  self._local_map.add_keyframe(..., pts_prev=prev_kps[:max_pts], pts_curr=kps[:max_pts])
  - prev_kps[:max_pts] and kps[:max_pts] are NOT matched pairs
  - Should use track.good_prev and track.good_curr from LK tracking

  6. Loop Closure Edges Have Wrong Scale (loop_closure.py:458-462)

  - Loop closure estimates unit-scale translation from Essential Matrix
  - Adds edge with t_ij=loop.t (unit) to a metric-scale graph
  - Optimizer fights between metric odometry edges and unit-scale loop edges

  Fix: Scale loop closure translation by current scale estimate:
  t_ij = loop.t * self._scale_recovery.scale

  7. Loop Detector State Not Reset (odometry.py:333-337)

  - reset() recreates pose graph, local map, scale recovery
  - Does NOT reset _loop_detector — BoW database, vocabulary, score history persist across sequences
  - Running run() twice on same instance mixes sequences

  ---

  🟠 ARCHITECTURAL GAPS (Research Paper Standards)

  1. No Ablation Studies

  The README reports numbers but doesn't show:
  - PnP vs Essential Matrix only
  - With/without loop closure
  - With/without pose graph optimization
  - With/without local map (pure pairwise VO)
  - Different keyframe selection strategies

  2. Scale Recovery Is Fragile

  - Ground-plane RANSAC assumes dominant plane = ground
  - Fails on: parking garages, hilly terrain, tunnels, off-road
  - No fallback or validation (e.g., IMU, stereo, semantic segmentation)
  - EMA smoothing (α=0.3) is ad-hoc — no uncertainty quantification

  3. No Dynamic Object Handling

  - All moving objects (cars, pedestrians) become "landmarks"
  - Causes drift in dynamic scenes
  - Modern VO/SLAM papers use: semantic segmentation, motion masking, or dynamic object detection

  4. Unbounded Map Growth

  - LocalMap.prune() only caps at 3000 points by observation count
  - No spatial hashing / redundancy removal
  - Long sequences → memory bloat

  5. No Marginalization / Sliding Window

  - Pose graph grows with every keyframe forever
  - No keyframe culling / marginalization for long-term operation

  6. Hard-Coded KITTI Assumptions

  - Camera height = 1.65m (KITTI-specific)
  - Ground plane = Y-down (KITTI camera frame convention)
  - Won't work on EuRoC, TUM, KITTI-360, or custom datasets without code changes

  ---

  🟡 QUALITY & REPRODUCIBILITY ISSUES

  1. Numerical Jacobians in Scipy Backend (optimizer.py:415-448)

  - Finite differences (eps=1e-6) are slow and imprecise
  - For a paper, implement analytical SE(3) Jacobians

  2. LM Implementation Flaw (optimizer.py:402-407)

  # Current: applies step FIRST, then checks cost
  T_new = T_old @ se3_exp(xi)  # step applied
  new_cost = graph.total_cost()
  if new_cost < total_cost:
      lam = max(lam / 3, 1e-10)
  else:
      lam = min(lam * 3, 1e6)  # but step was already kept!
  - Proper LM: reject step if cost increases, retry with higher λ

  3. Misleading API Names

  - kf_parallax_deg → actually pixels (median optical flow magnitude)
  - _median_parallax_deg docstring claims "angular parallax" but returns pixel flow

  4. Loop Closure Edge Weight Heuristic (loop_closure.py:455-457)

  loop_information = min(loop.n_inliers / 20.0, 5.0) * np.eye(6)
  - Not derived from covariance — just a hand-tuned scalar
  - For a paper, derive from RANSAC inlier geometry

  5. No Configuration Management

  - All hyperparameters hard-coded in constructors
  - No YAML/JSON config for reproducibility
  - Hard to sweep parameters for ablation

  6. Missing Tests

  - No integration test with real KITTI data
  - smoke_test.py uses synthetic blobs (too easy)
  - No CI/CD, no regression benchmarks
